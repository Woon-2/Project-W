경로 안내 연출 (Path Guidance) 설계 검토

플레이어가 맵에서 나아가야 할 경로를 알려주는 시각 연출 · 엔진 재사용성/난이도 종합 검토 · 2026-06-21

목표 — 맵 상에서 다음 목적지로 향하는 경로를 시각적으로 안내한다. 경로 데이터는 Unity에서 저작하여 추출/임포트하며, 우리 엔진의 기존 렌더 파이프라인을 최대한 재사용해 구현 비용 대비 연출 효과가 높은 방법을 고른다.

1. 재사용 가능한 엔진 자산 (난이도 판단 근거)

자산핵심 특성경로 연출 활용
TrailPipeline
trailPipeline.* / trail.hlsl		 카메라-페이싱 리본 스트립. 명시적 정점 배열(TrailVertexCPU.pos, ≤32/draw), additive 옵션, 타일/스트레치 UV + currentSystemTime 스크롤. 흐르는 빛 줄기에 거의 그대로 사용. 최고의 재사용성.
EnergyOrbPipeline
energyOrb.hlsl		 SceneColorHDR에 additive 자체발광 포인트 스프라이트(블룸 전). 둥근 soft-dot, HDR 색. 단 몬스터 submesh 스키닝에 결합(spawnFromMonster). 빛나는 구체 룩 재사용 가능. 단 경로용은 스키닝 의존성을 떼어낸 경량 변형 필요.
BillboardPipeline /
MeshParticlePipeline		 텍스처-시트 빌보드 / 3D 메시 파티클(회전·UV프레임). 파티클 시스템 전반 가동 중. 화살표 스프라이트 또는 3D 화살표 메시 배치에 사용.
TerrainHeightField
terrain.hpp		 getHeightAt(x,z) 양선형 높이 + getNormalAt 표면 노멀. 단 지형은 청크 스트리밍(TerrainChunkManager)이라 해당 청크 조회 필요. 임의 경로점을 지면에 투영 + 노멀 정렬. 모든 지면 밀착 연출의 공통 기반.
MarkerDef 섹션
markerDef.hpp / LevelMarker.cs		 chunks_index.bin의 Marker 섹션을 서버·클라가 함께 파싱. {type,name,pos,orient,scale}. TerrainExtractor가 베이크. 경로 데이터 Unity→엔진 추출의 기성 통로(아래 4장).
worldToScreen + UIPipeline 월드→스크린 투영(데미지 넘버에서 사용 중) + 9-slice/스프라이트 HUD. 화면 가장자리 나침반(보조 연출)에 사용.
데칼 시스템 — 없음 지면에 텍스처를 투영하는 전용 데칼 파이프라인이 현재 없음. 지면 투영 룬/경로(방법 E)는 신규 파이프라인 필요 → 난이도 상승 요인.

＊블룸: EnergyOrb·Trail의 additive 출력은 SceneColorHDR → 블룸 패스로 들어가 발광이 공짜로 입혀짐. 지면 밀착 연출은 모두 TerrainHeightField로 경로 폴리라인을 지면에 재투영하면 Unity Y 정밀도와 무관하게 지면에 딱 붙는다.

2. 연출 방법 후보 (5종 + 보조 1종)

A. 지형 화살표 (제안 1)

지면을 따라 화살표를 배치해 방향을 직접 지시

Billboard / MeshParticle 재사용 배치·정렬 로직 신규
  • 방향성이 가장 명확(화살표는 곧 방향). 초보자 친화.
  • 게임적·인위적으로 보이기 쉽고 "마법적" 분위기와 거리.
  • 경사·요철에서 클리핑/뜨는 느낌 → 노멀 정렬 + 높이 오프셋 필수.
시각 효과
명확하나 평범 ●●●○○
구현 난이도
낮음~중 ●●○○○

신규 파이프라인 없음. 작업: 경로 등간격 샘플 → 지면 노멀 정렬 → 화살표 에셋 + 스크롤/펄스.

B. 빛나는 구체 흩뿌리기 (제안 2)

경로에 자체발광 구체를 일정 간격으로 배치

EnergyOrb 룩 재사용 스키닝 의존성 분리 필요
  • 부드럽고 마법적·앰비언트. HDR+블룸 발광이 공짜.
  • 방향성이 약함 — 점들의 나열에서 진행 방향을 유추해야 함.
  • EnergyOrb는 submesh 스키닝에 묶여 있어 경량 glow-sprite 경로(또는 additive 빌보드)로 재구성 필요.
시각 효과
아름다움 ●●●●○
구현 난이도
낮음~중 ●●○○○

빌보드 additive + soft-dot로 가면 Low. EnergyOrb 파이프라인 정식 재사용이면 Medium(스키닝 분리).

C. 흐르는 빛의 리본 추천

지면을 따라 흐르는 한 줄기 빛(물줄기/에너지 강)

TrailPipeline 직접 재사용 방향성 강함
  • 연속적이고 우아. 타일 UV 스크롤이 목적지 방향으로 흐르며 방향을 명확히 전달.
  • TrailPipeline을 거의 그대로 재사용 + additive/HDR 블룸.
  • 리본이 카메라-페이싱이라 지면 스침각에서 어색 → 지면-정렬 변형(노멀 기준)이 바람직.
  • 32정점/draw 한계 → 긴 경로는 세그먼트 체이닝.
시각 효과
우아+직관 ●●●●●
구현 난이도
중 ●●●○○

작업: 폴리라인 리샘플 → 지면 높이 conform → 세그먼트 체이닝 → 스크롤 UV 배선 → 플레이어/목적지 근처 페이드.

D. 길잡이 정령(Wisp) 추천(보완)

밝은 구체가 플레이어 앞에서 경로를 따라 날아감

EnergyOrb + Trail 재사용 경로추종 무버 신규(경량)
  • 움직임으로 방향을 100% 전달. 맵 전체를 칠하지 않아 깔끔, 긴 경로에도 비용 일정.
  • 정석적 연출(Fable의 빵부스러기, Ori). 꼬리 트레일 붙이면 혜성 룩.
  • 국소 방향만 보여줌(전체 경로 미표시) → 방법 C와 병행 시 최상.
시각 효과
매력+직관 ●●●●○
구현 난이도
낮음~중 ●●○○○

경로추종 무버는 단순(리드 거리/속도/재출발). 렌더는 구체+트레일 재사용. 핵심은 손맛 튜닝.

E. 지면 투영 룬/텍스처 경로

지면에 텍스처(룬/점선/화살표)를 칠한 경로

데칼 파이프라인 없음 → 신규
  • 지면 밀착·가독성 최고, "퀘스트 길" 느낌. 텍스처 안에 화살표로 방향까지.
  • 전용 데칼 시스템이 없음. (a)진짜 데칼=고비용, (b)지면 conform 스트립 메시=중간.
  • 경사면 z-fighting/관통 처리, 신규 코드 최다.
시각 효과
최고 가독 ●●●●●
구현 난이도
중~높음 ●●●●○

(b) 스트립 메시 경로는 사실상 "지면-정렬판 방법 C". 둘을 합치면 한 파이프라인으로 수렴 가능.

F. 화면 가장자리 나침반 (보조)

2D HUD 화살표가 다음 목적지를 가리킴

worldToScreen + UI 재사용
  • 목적지가 화면 밖일 때 강력. 어떤 3D 방법과도 병행 가능.
  • 단독으로는 "연출"이라기보다 기능적 HUD. 메인 연출의 보완재.
시각 효과
기능적 ●●○○○
구현 난이도
낮음 ●○○○○

메인 후보가 아니라, 선택한 3D 연출에 얹는 옵션으로 검토.

3. 종합 비교

방법방향 전달분위기엔진 재사용 신규 파이프라인난이도맵 점유
A. 지형 화살표매우 명확게임적 Billboard/MeshParticle불필요낮~중중
B. 빛나는 구체약함마법적 EnergyOrb(분리)경량 신규 가능낮~중중
C. 흐르는 빛 리본 ★강함(흐름)우아·마법적 Trail 직접불필요(변형 권장)중경로 전체
D. 길잡이 위습 ★강함(움직임)매력적 Orb+Trail무버 신규(경량)낮~중국소
E. 지면 투영 룬명확(텍스처내)퀘스트감 신규 필요데칼/스트립 신규중~높경로 전체
F. UI 나침반명확(화면밖)기능적 worldToScreen+UI불필요낮음없음(HUD)

4. Unity에서 경로 저작 → 추출/임포트

경로는 곧 순서가 있는 점들의 폴리라인이다. 우리 추출 통로는 이미 chunks_index.bin + TerrainExtractor 한 곳으로 모여 있으므로 세 단계로 옵션이 갈린다.

옵션Unity 저작 방식추출/파싱 변경평가
① LevelMarker 빵부스러기 LevelMarker를 점마다 배치, markerType="PathPt", markerName="<pathId>_<index>" 익스포터 무변경. 클라/서버가 type 필터 후 name의 index로 정렬 가장 빠른 착수. 점 많으면 저작이 번거로움
② Path 컴포넌트 + 신규 섹션 PathMarker MonoBehaviour가 waypoint 리스트(또는 Unity Spline) 보유, 드래그로 곡선 저작 TerrainExtractor에 "Path" 섹션 베이크 추가 + 클라/서버 파서 추가 생산용 권장. 저작 쾌적, 데이터가 1엔티티로 깔끔
③ Spline 리샘플 베이크 ②와 동일 저작 + 추출 시 곡선을 등호장(等弧長) 리샘플해 균일 폴리라인으로 굽기 ②의 확장(추출기에서 리샘플) 리본/구체 간격이 균일 → 연출 품질↑. 권장

런타임 지면 conform. 어느 옵션이든 임포트한 폴리라인의 XZ만 신뢰하고, Y는 클라에서 TerrainHeightField::getHeightAt로 재투영(+소량 오프셋)한다. → Unity Y 정밀도/지형 수정과 무관하게 항상 지면에 밀착. 노멀 정렬이 필요한 화살표/스트립은 getNormalAt 사용. 경로는 게임플레이가 아닌 연출 데이터이므로 (Zone처럼) 클라 단독 처리도 가능.

권장 진행: 옵션 ① 로 빠르게 프로토타입 → 연출 확정 후 ②/③ 으로 생산 파이프 정식화. 추출 데이터 형태(폴리라인)는 셋 다 동일하므로 연출 코드는 그대로 재사용된다.

5. 추천

주연출: C. 흐르는 빛의 리본  ＋  보완: D. 길잡이 위습

C는 TrailPipeline을 거의 그대로 재사용하면서 흐름 방향으로 방향성을 강하게 전달하고, additive/HDR 블룸으로 "마법적인 길" 분위기를 살린다 — 재사용성·연출효과·방향성의 균형이 가장 좋다. 유일한 추가 작업은 카메라-페이싱 리본을 지면-정렬로 바꾸는 변형 정도.

D를 함께 두면 긴 경로에서 "지금 당장 어디로?"를 움직임으로 못박아 주며, C가 깔아둔 빛 줄기 위를 위습이 흐르는 그림이 완성된다. 둘 다 EnergyOrb/Trail 자산을 공유해 추가 비용이 작다.

대안: 빠른 착수/최소 위험을 원하면 B(빛나는 구체, 제안 2)가 가장 가볍다. 가독성 1순위·"퀘스트 길" 톤을 원하면 E지만 신규 파이프라인 비용을 감수해야 한다. 어떤 선택이든 F(UI 나침반)는 화면 밖 목적지 보완으로 저비용 추가 가능.
